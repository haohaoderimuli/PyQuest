# 企业第一周作业包 · 渠道日报脚本

一句话：**这是一份工单，不是教程。** 前 39 关是「给你题目，写一段能跑的代码」；这里给你一份需求、一份脏数据、一个空目录，你要交付一个别人敢让调度器每天跑的脚本。

## 场景

你入职某电商数据组第一周。组长在群里说：

> 下游看板每天早上 8 点读 `report.json`。现在这份文件是我用 Excel 手工导的，容易漏。你写个脚本，从订单 CSV 直接出，放到调度器上。下周一之前给我，要能换人维护。

没有更细的需求了。**剩下的口径、边界、错误处理，是你要问清楚或自己定下来并写进 README 的** —— 这就是第一周真正的工作。

## 时间安排（模拟一周）

| 关卡 | 时点 | 你要交什么 | 核心能力 |
| --- | --- | --- | --- |
| [TASK 01](TASKS/01-first-script.md) | 周一上午 | `daily_report.py` | 把需求翻译成代码、参数入口 |
| [TASK 02](TASKS/02-tests.md) | 周一下午 | `test_daily_report.py` | 证明口径没写错、测试能抓回归 |
| [TASK 03](TASKS/03-robust.md) | 周二 | 异常 / 日志 / 退出码 / 幂等 | 让无人值守的调度器敢调 |
| [TASK 04](TASKS/04-delivery.md) | 周三～周五 | README / Makefile / 依赖 / Git 历史 / 交付清单 | 换个人接得住 |

四关是**累加**的：TASK 04 验收时会连带跑 01–03，不是各写各的四个小脚本。

## 怎么开始

```
cd assignment/workspace
code .                       # 用 VS Code 打开这个空目录
python -m venv .venv
.venv\Scripts\activate
cd ..
python check.py --task 1     # 边写边验
```

## 验收不是自评

`check.py` 在本机真跑：

- 用两份不同数据执行你的 CLI，比对 JSON 的每个数字（防写死答案）
- 真跑你写的 unittest，并**把你的脚本改坏一次**再跑一遍，测试必须变红（变异测试，证明测试真在测口径）
- 造文件不存在、金额非数字、CSV 缺列三种故障，检查退出码与错误信息
- 同参数跑两次比对输出字节（幂等）、检查 import 不产生副作用
- 查 `.git` 里的真实提交次数、README / Makefile / .gitignore 的内容

站内「第一周作业」视图可以下载任务书和验收脚本，但**平台不替你判**：码在你本机，成绩也只在你本机。勾选框是自评，不写 PyQuest 通关记录、不加 XP。

## 参考解怎么放

`solution/` 里有完整可跑的 `daily_report.py`、`test_daily_report.py` 和交付文件示例。**卡住 20 分钟再看**，而且看完要关掉自己重写一遍 —— 照抄能让 check 全绿，但学不到东西。参考解在 `workspace` 之外，不会干扰验收（`check.py` 只认 `workspace/` 里的文件）。

## 做完之后

把 `workspace/DELIVERY.md` 填好，连同 `python check.py` 的全绿输出一起交。这份东西可以直接当作品附件，比"我学过 Python"有用得多。

## 已知边界（不吹牛）

- 不模拟真实调度器（Airflow / cron）、不发邮件、不接数据库。输入是 CSV，输出是 JSON。
- 不需要第三方库，所以 `requirements.txt` 可以是空的注释；但**必须存在**，因为企业里换人接手第一件事就是找依赖清单。
- `check.py` 只在本机验证，不联网、不上传你的代码。
